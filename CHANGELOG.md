- **Drafts: approve by template version, leave odd drafts out.** `design-journey` teaches the `templateId` / `templateUpdatedAt` filter keys (decide only the version the user read) and the `odd` filter: count `odd: "only"` before any filter approve, show those drafts, and approve with `odd: "exclude"` by default. Notes `drafts_too_many_odd` and that unknown filter keys are refused.
- **Drafts: size before you decide.** `design-journey` covers `drafts_get` and `drafts_count`, uses the server `asOf` that `drafts_list` now returns, and passes `expectedCount` on a filter `drafts_decide` (refused with `draft_count_changed` when the set changed). `launch-initiative` lists the new tools.
- **Journey send drafts.** `design-journey`: `SEND_MESSAGE` (template mode) and `SEND_EMAIL` take `delivery: immediate | draft` and emit `SENT`, the optional `SKIPPED` (Smart Sending's cap) and, with `draft`, the optional `REJECTED`; the "no signal may be left unwired" rule now names the optional handles. New "Hold sends for approval" section: when to suggest it, setting it, wiring `REJECTED`, the limits (no free-text WhatsApp, SMS, Instagram, Messenger or Transactional), reviewing on the Drafts tab or with `drafts_list` / `drafts_decide`, never approving without the user's explicit yes, and reconnecting `/mcp` when the client's schema predates `delivery`. `email-templates`, `launch-initiative`, `manage-participants` and `boom-overview` point to it, and `launch-initiative` gains a "nothing sent: check for waiting drafts" row.

- `connect-your-data`: match the app. Connections live under **Integrations → Directory** (there is no "Settings → Data Sources"); **Save** runs the connection test, and **Test connection** is on the connection page; there is no SSL setting. Saving a connection does not create its sync: Boom switches it on, then you build sources from **Integrations → Syncs** in four steps. Skio is a Directory card; Shopify is installed from a link Boom sends. `whatsapp-templates`: the app's template form always submits **UTILITY**, so MARKETING and AUTHENTICATION templates go through `templates_create`.

- `design-journey`: document the `goal` input on `MANAGE_CONVERSATION` (per-step agent instructions on top of the initiative objective, AGENT mode only, reaches new runs only), how to set and read it over MCP, and why it is not a second objective. Also corrects the `inactivityTimeout` range: any value up to `24h`, not `1h`–`24h`.

- **Email over MCP.** Add `email-templates`: `email_templates_list/get/create/update`, a block `document` vs hand-written `html` (exactly one, rendered and sanitized server-side, `removed` lists what was stripped), unknown fields rejected, DRAFT → PUBLISHED via `status`, `confirm: true` to change a live template, the one-way blocks → HTML conversion, the top-level-only footer, and sending through a journey's `SEND_EMAIL` node. `design-journey` drops its stale "email isn't authorable over MCP" note: `SEND_EMAIL` is in the node table with its successor rule and publish checks, and `journeys_email_templates` is in the tools. `launch-initiative` and `manage-participants` document that launch publishes email journeys too and that email participants enroll with `email`.

- **Install is one command, and the skills now actually auto-update.** Three changes that only work together:
  - Fixed the bundled MCP server. `plugins/boom/.mcp.json` pointed at `mcp.useboom.ai`, a host with no DNS, with an `Authorization: Bearer ${BOOM_API_KEY}` header that Boom's OAuth-only MCP server rejects anyway. It's now `https://www.useboom.ai/mcp` with no header, so access follows the user's Boom login and there is no API key anywhere in the install path. That's also the URL the docs publish, which matters because Claude Code matches plugin-provided MCP servers against manually configured ones by endpoint: an identical URL means one connection instead of two copies of Boom's tools.
  - Plugin distribution is **commit-SHA versioned**: dropped the pinned `version` from `plugins/boom/.claude-plugin/plugin.json`, so every push to this repo is a new version. With a pinned version, pushing skills never reached installed users, because Claude Code sees the same version string and keeps the cached copy. `validate.mjs` now treats `version` as optional, and still requires semver if it's set.
  - The installer also **migrates customers off `npx skills add`**. That path copies skills into `.agents/skills/<name>/` and symlinks them from `.claude/skills/<name>`, and the copies never update; beside the plugin they'd surface every Boom skill twice under two names, with Claude free to pick the stale one. The installer moves copies it can attribute to us into `.boom-skills-backup-<date>/`, prunes only our entries from `skills-lock.json`, and reports rather than guesses on copies with no lockfile proof (which is what global installs look like). It moves instead of deleting, so a wrong call costs a drag-and-drop. `--no-clean` opts out.
  - Added `@useboom/skills-setup` (`packages/skills-setup/`): a zero-dependency `npx` installer that writes the marketplace, the enabled plugin, and `autoUpdate: true` into a Claude Code settings file. It exists because auto-update is a declarative settings value that third-party marketplaces default to **off**, and no `claude plugin` flag turns it on. Merges additively, backs up the previous file, refuses to overwrite malformed JSON, and takes `--scope`, `--yes`, `--no-auto-update`, `--settings`, `--print`. Released from CI with provenance on a `v*` tag.

Teaches the core mental model (journey = the flow you own; the live conversation = the AI driving toward your objective; CDP = your contacts) and points to segments, the shared inbox, and common use cases as next steps.
